# Roadmap / 长期路线图

按可验证的里程碑推进。以下是计划，不代表已经实现。

| 里程碑 | 目标 | 完成标准 |
|---|---|---|
| v0.1 · 初始闭环 | JSONL → 三类认证检测 → 离线证据报告 | 可复现演示、边界测试、输入错误、CI、局限说明 |
| v0.2 · 真实日志 | OpenSSH 日志适配器 | 支持 RFC 3164 `sshd` password 成功/失败、可配置年份/时区、无关行跳过、坏认证行定位、正反样例；与归一化输入检测一致 |
| v0.3 · 检测评估 | 标注场景与评估命令 | 明确事件/告警匹配标准；TP/FP/FN、precision/recall；样本来源和限制公开 |
| v0.4 · 调查体验 | 多日志与时间线 | 来源可追溯、关联依据可解释、过滤与导出、报告安全测试 |
| v0.5 · 规则工程 | 规则配置、允许列表、回归集 | 配置校验、误报案例、变更前后效果对比 |
| v0.6 · 系统能力 | 性能基准与批次状态改进 | 公开机器/数据规模/测量脚本，吞吐量与内存曲线，无虚构数字 |
| v1.0 · 可展示作品 | 完整案例与稳定接口 | 固定版本、可录制演示、架构取舍、真实评估、可复现安装 |

## Next: SSH ingestion

- [ ] 定义接受的 OpenSSH 日志变体，先做带完整 ISO 时间的一种格式。
- [ ] 将 `Failed password` 与 `Accepted` 转成统一模型，保留原始行号。
- [ ] 明确不匹配行与损坏认证行的区别，避免悄悄丢失关键日志。
- [ ] 增加 IPv6、invalid user、publickey、普通系统噪声等样例。
- [ ] 比较 adapter 与 JSONL 路径的告警证据是否一致。
- [ ] 写一页分析：采集链路丢失或格式漂移如何导致漏报。

## Development rhythm

不启用定时开发。每次继续时先读 `docs/progress.md`，从当前里程碑选择一个小任务，验收后更新进度。不要按日期自动宣称里程碑完成。功能变更应有可解释的提交和验证结果，不为增加提交数量制造无意义改动。
