# Learning path / 把项目变成自己的能力

项目由 AI 辅助开发。你需要能够独立解释、修改和验证实现，才能在面试中讲清楚它。

## First session: run and investigate

1. 运行 README 中的演示命令，打开报告。
2. 回到样例的第 2–7 行，解释为什么产生两个告警，以及它们为什么可能属于同一个事件。
3. 把失败记录分散到超过五分钟，预测结果，再运行确认。
4. 把部分日志移到另一个主机，解释告警变化。
5. 把阈值调成 6，预测三个规则各自的结果。

## Second session: read and change

按 `models.py → ingest.py → engine.py → report.py → cli.py` 阅读。画出一条事件怎样进入窗口、怎样过期、何时触发、何时抑制重复告警。自己为一个误报场景写测试，再修改规则或参数观察影响。

## Third session: defend your design

回答这些问题，并把结论写进开发笔记：

- 为什么不能只数整个文件的失败次数？
- 为什么规则要按目标主机分组？共享 NAT 会造成什么误报？
- 同一秒发生的失败和成功能否证明因果？
- 输入 SHA-256 能证明什么，不能证明什么？
- 为什么日志里的用户名必须经过 HTML 转义？
- 为什么三个合成场景全过也不等于检出率 100%？

## Resume evidence

当前可以验证的项目表述：

> 基于 Python 实现离线认证日志分析工具，完成事件标准化、三类滑动窗口规则与可追溯证据报告；设计边界和异常输入测试，并建立跨平台 CI。

在你真正理解并参与修改对应功能后，再使用这段表述。未来补充真实完成的工作：接入了哪些日志源、如何定义标签和指标、在哪种环境处理了多少事件、误报如何下降。每个数字都要有脚本、数据和提交支撑。
